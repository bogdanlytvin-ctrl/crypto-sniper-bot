# FTOS — польовий довідник техніка FPV

**Інструмент рем-бригади для діагностики й ремонту FPV-дронів.** Працює офлайн, з телефона й з ПК.
Створено під реальні потреби військових/волонтерських майстерень: швидко, без води, тільки перевірені дані.

> **Принцип:** інструмент **підказує** — фінальна перевірка завжди на технікові.
> Кожна підказка має статус довіри й посилання на джерело. Ми не вгадуємо пінаути: помилка тут = спалена плата в когось у руках.

## Інструменти (11)

| # | Інструмент | Маршрут | Що робить |
|---|-----------|---------|-----------|
| 1 | **Діагностика** | `/diagnose` | Симптом → дерево перевірок (огляд / мультиметр / Betaflight) → ймовірна причина + крок фіксу. Кожна перевірка прив'язана до падів **саме твоєї плати**. Фільтр симптомів за тим, що на борту. |
| 2 | **Карта підключення** | `/wiring` | FC + RX + VTX + GPS → UART-и, пади, живлення, навхрест TX↔RX, налаштування Betaflight. Кнопка **«схема падів»** — згенерована з профілю плати. |
| 3 | **Журнал ремонту** | `/journal` | Локальний облік: борт → симптом → причина → запчастини. Аналітика (найчастіші причини/плати/запчастини, час). **Експорт CSV** (звіт командиру) / JSON + імпорт. Без хмари. |
| 4 | **Облік батарей** | `/batteries` | Парк LiPo: цикли, внутрішній опір, статус (бойова/storage/брак). Експорт/імпорт. Локально, без хмари. |
| 5 | **Прошивки** | `/firmware` | Правильний BF/iNav target для плати + чесний чек-лист прошивки (DFU, backup) + базові CLI-пресети. |
| 6 | **Опитати плату** | `/connect` | Підключення FC по USB (MSP через Web Serial, **desktop Chrome/Edge**) → variant/версія/target + **живий стан**: які сенсори бачить плата (надійно) і що блокує arming (best-effort для BF). Зіставлення з базою. |
| 7 | **Чек-листи** | `/checklist` | Передполітний / приймання / профілактика / **failsafe за роллю** (камікадзе vs розвідка) / **OPSEC-гігієна даних** — за реальними причинами відмов. |
| 8 | **Звірка даних** | `/verify` | Технік піднімає статус плат і дерев `draft → manual_checked → field_tested`. Експорт/імпорт звірок — один звіряє, роздає бригаді. |
| 9 | **Довідник** | `/reference` | Частоти 5.8 ГГц (Raceband), потужність VTX, LiPo, KV моторів, пропи, ELRS, **ESC-прошивки**, **РЕБ і діапазони · оптоволокно**, **планувальник частот рою** — таблиці з джерелами. |
| 10 | **Рецепти збірок** | `/recipes` | Стандартизовані борти під роль (5" удар, 7" далекобій, 10" бомбер, крило-розвідка): BOM + прошивка + ключові налаштування. Для масовості майстерні. |
| 11 | **Власні плати** | `/boards` | Редактор: додай плату/ревізію (UART/BEC/target), якої немає в базі — зʼявиться в усіх інструментах. Локально, завжди `draft`, експорт/імпорт. |

## Статус даних (чесно)

Кожен профіль і дерево має статус довіри:

| Статус | Значення | UI |
|--------|----------|-----|
| `draft` | заповнено, **не звірено** | 🟡 жовте попередження |
| `manual_checked` | звірено з **офіційним мануалом** | 🟢 зелений бейдж |
| `field_tested` | підтверджено на **реальному залізі** | 🟢 зелений бейдж |

### Плати: **16 / 16 — `manual_checked`**

Усі профілі звірено з офіційними джерелами (ArduPilot hwdef, мануали виробників, перевірені огляди).
По ходу звірки виправлено реальні помилки (напр.: Matek F722-SE **не має 9V BEC**; JHEMCU GHF405AIO має **10V**, не 9V; SpeedyBee F405 V4 UART4 = **Bluetooth**, не GPS).

### Діагностика: **23 симптоми · 91 перевірка · 144 причини** (усі `draft`)

Складено за стандартами Betaflight / ExpressLRS / DJI та практикою польового ремонту. **Не звірено живим ремонтом** — статус `draft`, технік підтверджує через `/verify`.

`немає відео` · `немає лінку з пультом` · `не армиться` · `мотор не крутить/не туди` · `плата не конектиться` · `немає GPS-фіксу` · `дрифт/«унітаз»` · `перегрів` · `немає OSD` · `немає телеметрії` · `просідає живлення` · `ESC desync` · `перезавантаження в польоті` · **`РЕБ vs залізо (лінк у польоті)`** · **`немає сигналу по оптоволокну`** · **`скид не працює`** · **`GPS Rescue / RTH не працює`** · **`дим / коротке замикання`** · **`не вирівнюється / гіро-акс`** · **`битий OSD-шрифт`** · **`не зберігає налаштування`** · **`стіки не рухають бари`** · **`перекидається на зльоті`**

Кожна причина має `confidence` (ймовірно / можливо) і `source_url`. Інструмент ніколи не каже «точно».

### Компоненти: **14** (усі `draft`)

- **Приймачі** (ELRS/CRSF): RadioMaster RP3, RadioMaster RP1, HappyModel EP2, BetaFPV ELRS Lite
- **Відео**: DJI O3, Walksnail Avatar HD, HDZero Freestyle V2 (цифрові) · RushFPV Tank Solo (аналог)
- **GPS**: Mateksys M10Q-5883
- **ESC**: BLHeli_S / BLHeli_32 / AM32 — за **родиною прошивки** (вона визначає телеметрію). ESC підключається стек-кабелем (мотори + VBAT + опційна телеметрія), а не як UART-периферія — це окрема гілка двигуна.
- **Скид/реліз**: серво-реліз, електромагнітний реліз — PWM-сигнал на серво-вихід + 5V, керування AUX. Окрема гілка двигуна; безпека: не має спрацьовувати на вмиканні/у failsafe.

Карта підключення має **візуальну схему падів** (SVG, згенерована з профілю) і **друк/PDF** для роботи з паперу в полі.

## Запуск

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # юніт-тести (Vitest)
npm run typecheck  # tsc --noEmit
npm run build      # продакшн-білд
```

Деплой: `git push` у `main` → **GitHub Actions** (typecheck + тести + build) → **Vercel** деплоїть автоматично. Жива адреса — `ftos-rho.vercel.app`.

### Офлайн (PWA)
Після першого відкриття застосунок працює **без мережі** (service worker + runtime-кеш). Можна «встановити як застосунок» на телефон/ПК. Дані-довідник вшиті в бандл — доступні офлайн повністю.

## Стек

Next.js 14 (App Router) · TypeScript · статичні JSON-профілі · IndexedDB (журнал + звірки + батареї) · Web Serial + MSP (опитування плати) · власний service worker (офлайн) · Vitest (59 тестів) · GitHub Actions (CI) · Vercel (авто-деплой).
Без бекенду, без акаунтів, без хмари — усі локальні дані лишаються на пристрої (opsec бригади).

---

## Приватність та безпека (аудитовано)

- **Жодної аналітики/трекерів/cookies** — усі скрипти same-origin, **0 зовнішніх викликів** у рантаймі. Застосунок **не «телефонує додому»**.
- **Дані локальні** — журнал, батареї, звірки в IndexedDB на пристрої; нічого не виходить у хмару.
- **Мінімальні залежності** (next/react) — мала поверхня атаки; `safeHref` на всіх зовнішніх посиланнях; без `eval`/`innerHTML`; без секретів.
- Встановлений PWA працює **повністю офлайн** після першого завантаження. Для закритого розгортання — роздавати статичний білд довіреним технікам, репозиторій **приватний**.

## Як додати / звірити

**Плату:** скопіюй файл у `data/boards/`, заповни з офіційного мануала, додай імпорт у `lib/data.ts` → `BOARDS`. Ревізія/варіант = окремий файл (F405 V3 ≠ V4; різні BEC-варіанти = різні файли).

**Дерево діагностики:** новий JSON у `data/flows/` (схема в `lib/diagnostics.ts`), імпорт у `FLOWS`. Кожна причина — з `confidence` і `source_url`. Цілісність дерев перевіряється автоматично (`validateFlow` у dev).

**Підняти статус даних:** через `/verify` (локально, з експортом для бригади) — не правлячи JSON. Для `field_tested` потрібна перевірка на реальному борту.

## Філософія

Це інструмент для людей, чиї помилки коштують дронів і життів. Тому:
- **тільки правда** — неперевірене явно позначене як `draft`;
- **джерело на все** — кожна підказка з посиланням;
- **межа чесності** — `field_tested` ставить лише той, хто реально тримав плату в руках.
