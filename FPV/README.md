# FTOS — база сумісності FPV-компонентів (MVP v0.1)

Одна функція: **FC + RX + VTX + GPS → готова карта підключення (UART-и, живлення, прошивка).**

## Структура даних

```
ftos/
├── board-profile.schema.json   # схема профілю польотного контролера
├── boards/                     # профілі FC (1 файл = 1 ревізія плати!)
│   └── speedybee-f405-v4.json
└── components/                 # профілі периферії (RX / VTX / GPS)
    └── radiomaster-rp3-elrs.json
```

## Як працює двигун сумісності (логіка для UI)

1. Користувач обирає FC + компоненти.
2. Для кожного компонента беремо `requirements` і шукаємо в профілі плати:
   - вільний UART з відповідним `recommended_for` (пріоритет) або `any`;
   - UART-и з `default_function` (напр. ESC telemetry) вважаємо зайнятими;
   - відповідний BEC за `voltage` і сумарним струмом.
3. Видаємо план: `RP3 → UART2 (пади T2/R2, навхрест TX→R2, RX→T2), живлення 5V` + `firmware_notes`.
4. Якщо UART-ів не вистачає або немає потрібної напруги — чесний конфлікт, а не мовчазна помилка.

## Правила наповнення бази (КРИТИЧНО)

1. **Тільки офіційні мануали.** Кожен профіль має `source_url`. Без джерела — не додаємо.
2. **Ревізія = окремий файл.** F405 V3 ≠ V4. Помилка тут = спалена плата в когось у руках.
3. **`verified.status`:**
   - `draft` — заповнено, не звірено (UI показує жовте попередження!)
   - `manual_checked` — звірено з мануалом другою людиною
   - `field_tested` — підтверджено реальним підключенням
4. UI **завжди** показує статус верифікації і лінк на мануал. Ми підказуємо, відповідальність за фінальну перевірку — на техніку.

## Валідація після MVP

Кинути лінк + 2 скріншоти у FPV-спільноти з чесним питанням
«чи треба таке, яких плат не вистачає»:
- Telegram-спільноти ремонту/збірки FPV (укр.)
- волонтерські майстерні дронів
- знайомі оператори з попереднього проєкту діагностики

Метрика успіху: ≥5 змістовних відповідей і ≥1 «додай плату X, користуюсь щодня».

## Чого НЕМАЄ у v0.1 свідомо

Flutter, LLM/RAG, фоторозпізнавання, акаунти, офлайн, діагностичні сценарії.
Стек: Next.js + статичні JSON + Vercel. Спершу валідація, потім фічі.

## Запуск (цей репозиторій)

```bash
npm install
npm run dev        # http://localhost:3000
```

Деплой: пуш на GitHub → імпорт у Vercel, нічого налаштовувати не треба (статичний білд).

## Як додати плату

1. Скопіюй `data/boards/speedybee-f405-v4.json`, заповни з офіційного мануалу.
2. Додай імпорт у `lib/data.ts` → масив `BOARDS`.
3. Постав `verified.status`: `draft` → після звірки `manual_checked`.

Компоненти (RX/VTX/GPS) — так само через `data/components/` і масив `COMPONENTS`.

## Статус даних

Усі поточні профілі — **DRAFT, заповнені по типових конфігураціях, НЕ звірені з мануалами**.
UI чесно показує це попередження. Перед публікацією: звірити кожен UART/BEC із
документацією виробника (лінки в `source_url` кожного файлу).
