## ГОЛОВНИЙ ФАКТ (без здогадок)

**Коду MFO Legal Bot у робочому просторі НЕМАЄ.** Перевірено вичерпно:
- Пошук по `.py/.html/.txt` за «мфо / мікрозайм / мікрофінанс / колектор / юрист» → 0 збігів (єдиний збіг «кредит» у `seven-src` — це сонячний лендінг SEVEN+).
- Корінь (`bot.py`, `database.py`, `payments.py`) = Crypto Sniper (імпортує `scanner/`, `trader/`).
- `admin/app.py` = адмін-панель Crypto Sniper (Signals/Trades/Positions).
- У `Desktop/проекти/` — лише scanner-sites.

**Висновок:** проект існує тільки як ТЗ (`project_legal_bot.md`). Аудитувати/тестувати код неможливо — його не написано. Отже відповідь на «чи допомагає людям зараз» — **ні, бо продукту ще немає.**

## ОЦІНКА КОНЦЕПЦІЇ: чи допоможе людям, ЯКЩО написати правильно

**Вердикт: ідея корисна і має реальний попит, АЛЕ за поточним ТЗ — недостатня і юридично небезпечна.**

### Чому небезпечна
Юрбот, що дає поради про борги за гроші, при помилці завдає прямої шкоди: пропущений строк, програна справа, неправильна заява. Тому є дві смертельні вимоги:

1. **Актуальність права — не «GPT з пам'яті».** LLM галюцинує номери статей і застарілі норми. Бот ОБОВ'ЯЗКОВО має тягнути чинні норми через RAG над першоджерелом (`zakon.rada.gov.ua`), інакше він активно шкодить.
2. **Дисклеймер.** «Не є юридичною консультацією, не замінює адвоката» — інакше правовий і репутаційний ризик для власника.

## ЩО БОТ МУСИТЬ ВМІТИ (на основі чинного законодавства 2026)

Досліджені чинні норми, які і є реальною цінністю для боржника:

| Норма (2026) | Як перетворити на корисну функцію |
|---|---|
| Денна ставка ≤ 1% | Калькулятор: чи МФО не перевищує ліміт |
| Сукупні платежі (тіло+%+пеня+штраф) ≤ **подвійний розмір кредиту** | Калькулятор переплати: «вам нараховують більше за закон» — найсильніша функція |
| «Паспорт споживчого кредиту» обов'язковий | Чек-ліст: що кредитор зобов'язаний був розкрити |
| Колектори — лише з **публічного Реєстру НБУ** | Перевірка колектора по реєстру → якщо немає = незаконний |
| Обов'язки колектора при 1-му контакті (ім'я, компанія, підстава, сума) | Скрипт «що вимагати від колектора» |
| Скарга до НБУ (втрата ліцензії = смерть МФО) | **Генератор скарги до НБУ** — найвища практична цінність |
| Прострочення кредитора → нарахування % припиняється | Пояснення + шаблон листа новому кредитору |
| Штраф колектору 3000–6000 НМДГ, 3 штрафи/рік = виключення з реєстру | Аргумент у скарзі |

Якщо бот це реалізує (а не загальні фрази від GPT) — він **реально допомагає**: рахує переплату, генерує скаргу, перевіряє легальність колектора.

## ТЕХНІЧНІ ВИМОГИ ДЛЯ РОБОЧОЇ ВЕРСІЇ

1. **RAG-шар**: індексація актуальних редакцій ЗУ «Про споживче кредитування» (1734-19), ЗУ про колекторів, постанов НБУ; джерело `zakon.rada.gov.ua` з датою редакції. Без цього «тягнути актуальну інформацію» = неможливо.
2. **Генератори документів**: скарга НБУ, лист про прострочення кредитора, заперечення — як шаблони з підстановкою (а не вільна генерація).
3. **Перевірка колектора** по реєстру НБУ.
4. **Платежі Stripe**: серверна перевірка статусу, ідемпотентність вебхуків, не довіряти клієнту.
5. **Захист даних**: користувачі діляться даними про борги/суди → шифрування, право на видалення (ЗУ «Про захист персональних даних»).
6. **Обов'язковий дисклеймер** у кожній юр-відповіді.

## Security ⚠️ (превентивно, коду ще немає)
- Платіжна логіка + персональні дані боргів = підвищений ризик; потрібен окремий security-аудит при написанні.

## Пропозиція +10%
Найсильніша монетизована функція — **генератор скарги до НБУ + калькулятор переплати «×2 тіла»**. Це конкретний результат, за який люди платять, і він прямо спирається на закон. Радив би будувати MVP саме навколо цих двох дій, а не «чат із юристом».
