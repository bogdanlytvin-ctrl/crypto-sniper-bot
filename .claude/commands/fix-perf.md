# /fix-perf — Пайплайн оптимізації продуктивності

Завдання: **$ARGUMENTS**

Працюй автономно через етапи. Зупинись лише при деструктивній дії.

## Етапи

### 1. ЗАМІР ДО (baseline)
- Якщо це Next.js/веб: збери bundle (`next build`), подивись розміри чанків, знайди важкі залежності
- Якщо є URL: спробуй виміряти час відповіді (`curl -w`), перевір Lighthouse-метрики якщо доступно
- Зафіксуй конкретні цифри ДО

### 2. ДІАГНОСТИКА
Запусти **bug-hunter** + **reviewer** (паралельно) з фокусом на performance:
- N+1 запити до БД
- Синхронні блокуючі операції замість async
- Відсутність кешу / pagination
- Великі bundle, невідкладені імпорти, не оптимізовані зображення
- Зайві re-renders (React), `use client` де можна Server Component

### 3. ОПТИМІЗАЦІЯ
Запусти **code-agent** для виправлень за пріоритетом (найбільший виграш першим). Кожна зміна — обґрунтована очікуваним ефектом.

### 4. ЗАМІР ПІСЛЯ
Повтори заміри з етапу 1. Покажи дельту ДО→ПІСЛЯ конкретними числами.

### 5. ЗВІТ
```
## Звіт: fix-perf | [дата]
### Проблема: [що повільно]
### Метрики ДО: [bundle/час/score]
### Знайдені вузькі місця: [список з file:N]
### Оптимізації: [що зроблено]
### Метрики ПІСЛЯ: [bundle/час/score] — дельта: [виграш]
### +10%: [наступний крок оптимізації]
```
